# 오늘, 할 일

검정 테마의 개인용 플래너입니다. 반복 시간표, 특별 일정, 카테고리별 할 일, 루틴과 마감을 한 화면에서 관리합니다.

## 실행

Node.js 22 이상이 필요합니다. 처음 실행할 때 OAuth 토큰 검증용 `jose` 패키지를 설치합니다.

```sh
cd /home/wnsgur/Dev/today-todo
npm install
node server.js
```

Linux용 npm이 설치되어 있다면 아래 명령도 같습니다.

```sh
npm run dev
```

브라우저에서 `http://localhost:4173`을 엽니다.

WSL에서도 Windows 브라우저로 같은 주소를 열 수 있습니다. 현재 작업 환경에는 패키지를 설치해 두었으므로 `node server.js`만 실행하면 됩니다. npm 실행 중 `WSL 1 is not supported`가 나오면 Windows용 npm이 선택된 경우입니다. 이 환경에서는 설치 명령을 `node '/mnt/c/Program Files/nodejs/node_modules/npm/bin/npm-cli.js' install`로 실행할 수 있습니다. 다른 환경에서는 Linux용 Node.js/npm을 설치하세요. 종료는 터미널에서 `Ctrl+C`, 다른 포트는 `PORT=4174 node server.js`입니다. 브라우저 저장소는 주소별로 구분되므로 같은 주소를 계속 사용하세요.

## 설정 위치

왼쪽 사이드바 맨 아래의 **설정**에서 기기 간 동기화, 알림, GPT 설정·도우미, 카테고리 관리를 엽니다. GPT 사용량 표시도 여기서 켜고 끕니다. 모바일에서는 상단의 **설정** 버튼을 사용합니다.

## 전체 보기와 주간 플래너

처음 열면 **전체 보기**가 표시됩니다. 일·월·화·수·목·금·토 순서의 시간표와 해당 주의 할 일·일정, 오른쪽 달력을 함께 봅니다. 이전/다음 주, **이번 주**, 날짜 입력과 달력 클릭으로 주를 이동하며 달력에는 현재 보는 주와 주차가 표시됩니다. 주차는 일요일부터 시작하며 그 일요일이 속한 달을 기준으로 셉니다.

- **주간 플래너 → 플랜 추가**에서 제목, 반복 요일, 시작·종료 시각, 적용 시작일, 카테고리를 설정합니다. **요일별로 시간 다르게 설정**을 켜면 선택한 요일마다 시작·종료 시간을 따로 입력합니다. 시간표의 빈 곳을 클릭하면 그 요일·시간으로 입력을 시작합니다. 매주 같은 시간표를 사용합니다. 종료 00:00은 당일 자정(24:00)을 뜻하며, 자정을 넘는 플랜은 요일별로 나눠 추가합니다.
- 전체 시간표에 세로 내부 스크롤을 두지 않고 시간 행을 압축해서 보여줍니다. 제목·할 일의 실제 줄바꿈 높이를 측정해 시간 행을 자동으로 늘립니다. 겹치는 일정으로 폭이 좁아지거나 모바일·화면 크기·글꼴이 바뀌어도 다시 계산합니다. 플랜 제목·메모 입력칸도 내용에 맞춰 늘어납니다. 모바일에서 7일을 볼 때는 가로로 이동할 수 있습니다.
- **전체 보기**에서 오늘과 과거 날짜의 플랜을 체크합니다. 미래 플랜은 미리 완료할 수 없습니다. 플랜 완료와 할 일 완료는 별도로 기록합니다.
- 플랜 변경은 적용 시작일 이후에 반영되며 이전 시간표와 완료 기록을 보존합니다. 삭제하면 오늘 이후의 미완료 플랜이 사라지고 과거 기록과 완료 기록은 남습니다.
- 플랜 추가·수정 창 또는 **주간 플래너** 목록에서 **달력에서 플랜 기록 보기** 토글을 켜면 해당 플랜이 달력 드롭다운에 표시됩니다. 기본값은 꺼짐이며, 끄더라도 완료 기록은 유지합니다. 선택한 플랜의 완료·미완료 날짜와 월별 수행률을 확인하고 과거 완료 체크를 변경할 수 있습니다.

## 카테고리와 할 일 배치

설정 또는 플래너의 **카테고리**에서 이름과 색상을 만들고 수정합니다. 할 일·루틴·플랜·일정에 할당할 수 있습니다. 예를 들어 월요일 20–21시의 운동 플랜과 월요일의 러닝머신 할 일에 **운동** 카테고리를 지정하면 러닝머신은 그 플랜 안에 표시됩니다.

할 일·루틴 추가/수정에서 **전체 보기에서 표시할 위치**를 선택합니다. 기본은 같은 날짜·카테고리의 수행 가능한 첫 플랜에 한 번만 배치하고, 시각이 있는 루틴은 그 시각이 플랜 시간 안에 있어야 포함합니다. **요일별 목록 맨 아래**를 선택하면 카테고리나 시각이 맞아도 시간표에 포함하지 않으며 다른 미배치 항목보다 아래에 표시합니다. 같은 카테고리의 플랜이 없거나 모두 일정으로 제외되면 그 요일 아래 목록에 표시됩니다. 카테고리 삭제는 연결만 해제하고 할 일과 플랜은 유지합니다.

## 특별 일정

상단 **일정 추가** 또는 왼쪽 **일정**에서 시작·종료 날짜, 시각/종일, 카테고리와 메모를 설정합니다. 입력한 날짜의 요일도 함께 표시합니다. 일·주·월 단위의 반복 간격, 주 단위 시작 요일과 반복 종료일을 지정할 수 있습니다. 주간 간격은 시작일이 속한 일요일 기준의 주를 사용합니다. 월 단위는 원래 시작일을 반복하고 없는 날짜는 월말에 배치합니다.

여러 날 일정은 시작부터 종료 시각까지 연속됩니다. 종일 일정은 종료 날짜까지 포함합니다. 반복 종료일은 각 발생의 시작 날짜 기준입니다. 수정·삭제는 반복 전체에 적용됩니다.

**겹치는 주간 플랜을 수행할 수 있나요?**에서 수행하지 않음을 선택하면 겹친 미완료 플랜 전체를 해당 날짜의 목표에서 제외합니다. 이미 완료한 기록은 유지합니다. 수행 가능을 선택하면 플랜이 계속 목표에 포함됩니다. 할 일 자체를 삭제하거나 자동 완료하지 않습니다. 겹치는 시간 블록은 나란히 표시합니다.

## 마감

할 일의 **날짜**는 계획한 수행일이며, 선택 입력인 **마감**은 실제 끝내야 하는 날짜와 시각입니다. 날짜를 옮겨도 마감은 그대로 유지되고 날짜 변경 창 아래에 표시됩니다. 수정 창의 **마감 지우기**로 제거합니다.

**예정된 일**은 미완료 항목을 마감 시각순으로 표시하고 마감 없는 항목은 계획 날짜순으로 뒤에 표시합니다. 계획일이 지난 항목도 마감이 있으면 표시하며 기한이 지난 마감을 먼저 보여줍니다. 완료한 항목은 제외합니다. 마감은 절대 시각으로 저장하며 표시·오늘 판정·입력은 접속 기기의 시간대를 따릅니다.

## 루틴

- **루틴 만들기** 또는 **나의 루틴 → 새 루틴**에서 할 일 없이도 루틴을 만듭니다. 기존 할 일·하위 할 일의 메뉴에서도 루틴으로 등록할 수 있습니다.
- 일·주·월 단위와 반복 간격(예: 2일마다, 2주마다), 주 단위의 요일, 시작·종료 날짜를 설정합니다. 종료일을 비우면 계속 반복합니다. 월 단위의 31일처럼 날짜가 없는 달에는 마지막 날에 반복합니다.
- 주 단위 간격은 시작일이 속한 주의 월요일을 기준으로 계산하며 시작·종료일을 모두 포함합니다.
- **수행 시각**을 선택적으로 입력합니다. **요일별로 시각 다르게 설정**을 켜면 요일마다 다른 시각을 지정하거나 일부 요일의 시각을 비워둘 수 있습니다. 주 단위는 선택한 요일, 일·월 단위는 7개 요일을 설정합니다.
- **전체 보기 시간표에 표시**를 켜면 시간에 맞는 같은 카테고리의 플랜 안에 표시하거나, 맞는 플랜이 없으면 해당 시각에 별도로 표시합니다. 체크박스·제목·시각을 한 줄에 놓고 위쪽 카테고리 색상 선으로 구분합니다. 루틴은 수행 시각만 나타내며 종료 시각을 설정하지 않습니다. 표시를 끄면 기존 할 일 배치 기준을 따릅니다. **맨 아래** 위치를 선택하면 시간표 표시가 해제됩니다. 완료 체크는 날짜별 할 일/하위 할 일 및 달력 기록과 연결됩니다.
- 루틴 시각은 날짜별 할 일에 함께 저장합니다. 루틴 설정을 바꿔도 과거·완료한 항목의 시각을 유지하며 오늘 이후 미완료 항목에 새 설정을 적용합니다.
- 루틴은 해당 날짜의 할 일로 자동 추가됩니다. 오늘부터 30일 앞과 현재 보고 있는 달까지 일정을 준비하고, 달을 이동하면 필요한 일정을 추가합니다.
- 달력의 **루틴·플랜 기록 보기**에서 루틴을 선택하면 완료(초록), 지난 미완료(빨강), 오늘 대기(노랑), 예정(파랑)을 확인합니다. 월별 수행률은 완료 / (완료 + 지난 미완료)로 계산하며 오늘 대기·미래 예정은 제외합니다. 날짜를 선택해 과거 기록도 완료로 표시하거나 취소할 수 있습니다.
- **나의 루틴**에서 수정·삭제합니다. 수정은 오늘 이후 미완료 일정에 적용되고 과거 기록·완료 일정은 남습니다. 삭제해도 과거 기록·완료 할 일은 유지됩니다. 특정 할 일의 날짜를 옮겨도 루틴 기록은 원래 반복일을 기준으로 표시합니다.

## 알림

**설정 → 알림 설정**에서 매일 알림을 켜고 시간을 정합니다. 기기 시간대를 사용하며 설정은 이 브라우저에 저장됩니다. 오늘 마감인 미완료 할 일은 계획 날짜와 관계없이 알림 맨 위에 시각순으로 표시하고, 그 뒤에 오늘 계획한 남은 할 일·루틴을 표시합니다. 두 조건에 모두 해당해도 중복 표시하지 않습니다. 알릴 항목이 없으면 알림을 생략합니다.

앱 안에는 전체 목록을 표시하고, **알림 허용**으로 브라우저 권한을 허용하면 시스템 알림도 보냅니다. 시스템 알림에는 최대 5개 제목과 나머지 개수를 표시하며 클릭하면 오늘 목록으로 이동합니다. **테스트 알림**으로 즉시 확인할 수 있습니다. 권한이 차단되거나 지원되지 않아도 앱 안의 알림은 동작합니다.

앱이 열려 있는 동안 약 15초마다 시간을 확인합니다. 절전·백그라운드 제한으로 알림이 늦어질 수 있습니다. 앱을 닫은 동안에는 예약 알림을 보내지 않으며, 그날 설정 시간이 지난 뒤 다시 열면 놓친 알림을 한 번 표시합니다. 브라우저 종료 상태의 알림은 별도의 Push 서버가 필요합니다. 시스템 알림은 HTTPS 또는 localhost 환경에서 지원됩니다.

## GPT 남은 사용량

**설정 → GPT 사용량 표시**에서 상단 영역을 켜거나 끕니다. 영역의 **×** 버튼으로도 숨길 수 있습니다. 끄면 진행 중인 조회와 30초 자동 조회를 중지하며 새로고침해도 숨김 설정을 유지합니다. 다른 탭에도 적용되고, 브라우저별로 저장됩니다. GPT 도우미는 사용량 영역을 숨겨도 사용할 수 있습니다.

기본 기준은 **방문자가 연결한 ChatGPT 계정**입니다. 현재 공개된 공식 OAuth 문서에는 방문자별 구독 잔여 비율을 조회하는 독립 API가 확인되지 않았습니다. 따라서 숫자를 추정하지 않고 조회 지원 대기 안내와 [ChatGPT 사용량 설정](https://chatgpt.com/settings/usage) 링크를 표시합니다. 모델 호출 권한만 승인받았다고 잔여 사용량 조회도 된다고 간주하지 않습니다. 이 상태에서는 불필요한 주기 조회를 하지 않습니다. 공식 사용량 API가 제공되면 서버의 `/api/usage`에서 기존 화면 형식으로 변환할 수 있습니다.

개인용 개발 환경에서 이전 Codex 사용량 기능을 보려면 명시적으로 로컬 모드를 켭니다. 화면에도 **서버의 로컬 Codex 계정**으로 표시하며 방문자의 계정 사용량과 구분합니다. localhost에만 바인딩할 수 있고 외부 서비스용 설정에서는 사용할 수 없습니다.

```sh
TODO_USAGE_MODE=local-codex node server.js
```

이 모드는 설치·로그인된 Codex CLI의 [`account/rateLimits/read`](https://learn.chatgpt.com/docs/app-server)를 사용합니다. `TODO_CODEX_BIN`으로 CLI 위치, `TODO_USAGE_STATUS_URL=http://127.0.0.1:8765/api/status`로 기존 대시보드를 지정할 수 있습니다. 계정이 보고하는 구간만 표시하고 30초마다 갱신합니다. 조회 실패 시 마지막 값과 갱신 실패 상태를 표시합니다. 사용량 조회 자체는 모델을 호출하지 않습니다.

## ChatGPT 구독으로 모델 호출

**설정 → GPT 설정·도우미**에서 방문자 각자의 ChatGPT 계정을 연결하고 해당 계정의 모델 목록을 선택합니다. 질문하면 서버가 사용자 OAuth access token으로 [공식 Responses API](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)를 호출하고 답변을 스트리밍합니다. 답변 중지·복사와 빠른 질문을 지원합니다. `store: false`, `stream: true`로 요청하며 `response.completed`를 받은 경우에만 완료로 표시합니다. 사용 한도 오류·미완료·연결 중단은 일부 답변을 보존하며 별도로 안내합니다. API key 방식으로 자동 전환하지 않습니다.

**오늘 남은 할 일도 함께 보내기**는 기본으로 꺼져 있습니다. 켜면 전송할 목록을 미리 볼 수 있고 오늘 미완료 항목의 제목·메모·우선순위·미완료 하위 항목을 보냅니다. 최대 20,000자까지 함께 보낼 수 있으며 질문은 4,000자 이내입니다. 도우미는 할 일을 수정하지 않습니다. 질문과 답변은 화면에만 유지하고 서버 로그나 브라우저 저장소에 저장하지 않습니다.

### 현재 가능한 범위와 등록

**현재는 서비스 등록 전 상태입니다. 실제 사용자 계정 로그인 및 모델 호출은 검증하지 못했으며 비활성화됩니다.** 화면과 OAuth·스트리밍 처리는 모의 응답으로 검증했습니다.

OpenAI 공식 안내상 원격 호스팅 앱의 ChatGPT 구독 사용은 [접근 신청](https://developers.openai.com/siwc/request-client-id)과 승인 확인이 필요합니다. [웹 로그인 문서](https://developers.openai.com/siwc/website)는 identity 권한을 다루므로, 발급받은 client가 구독 호출용 `resource.invoke`, `chatgpt.tokens.use.direct`, `offline_access`와 공개 Responses API 접근을 지원하는지 별도로 확인해야 합니다. 이 구현은 등록된 웹 client와 공개 문서의 구독 호출 계약을 연결한 준비 코드이며, 승인된 웹 client의 세부 계약에 따라 설정 또는 코드 조정이 필요할 수 있습니다. 로컬 OSS용 `dynamic_agent_client` 또는 기존 Codex CLI의 client ID를 공개 웹 서비스에 재사용하지 않습니다.

승인 시 확인할 정보:

- 앱의 OAuth client ID, 환경별 정확한 callback URL, token-endpoint 인증 방식.
- 이 원격 웹 앱에 대한 ChatGPT 구독 모델 호출 허용 여부와 승인된 scope/resource.
- 방문자별 잔여 한도 조회 API의 지원 여부, 권한, 응답 계약. 호출 권한과 별도로 문의합니다.

### 등록 후 설정

`.env.example`을 `.env`로 복사하고 등록받은 값을 설정한 다음 서버를 재시작합니다. `.env`는 Git에서 제외되고 서버가 자동으로 읽습니다.

```dotenv
TODO_PUBLIC_URL=https://todo.example.com
OPENAI_CLIENT_ID=oaiapp_발급받은값
TODO_CHATGPT_PLAN_ENABLED=true
OPENAI_TOKEN_AUTH_METHOD=none
```

위 client ID는 자리표시자이므로 실제 값으로 바꿔야 합니다. 구독 호출 승인을 받은 후에만 `TODO_CHATGPT_PLAN_ENABLED=true`를 설정합니다. confidential client로 발급받았다면 `OPENAI_TOKEN_AUTH_METHOD=client_secret_basic`과 서버 전용 `OPENAI_CLIENT_SECRET`을 추가합니다. secret을 채팅·브라우저 코드·Git에 넣지 마세요. callback은 **`https://todo.example.com/auth/chatgpt/callback`**이며 개발용은 **`http://localhost:4173/auth/chatgpt/callback`**입니다. 정확히 등록된 원본 주소로 접속해야 하며 `localhost`와 `127.0.0.1`을 혼용하지 않습니다.

사용자 토큰과 OAuth state·PKCE verifier·nonce는 서버 메모리에 보관하고, 브라우저에는 HttpOnly 세션 쿠키만 발급합니다. HTTPS에서는 Secure 및 `__Host-` 접두사를 사용합니다. ID token은 `jose`로 JWKS 서명·issuer·audience·만료·nonce를 검증합니다. 세션마다 CSRF 검증을 하고 토큰 갱신은 같은 세션에서 한 번씩 처리합니다. 연결 해제 시 refresh token 폐기를 시도하고 확인되지 않으면 사용자에게 안내합니다.

현재 서버는 **단일 인스턴스 개발용**이며 세션은 8시간 후 또는 서버 재시작 시 사라집니다. 공개 배포 전에는 암호화된 서버 저장소, 인스턴스 간 원자적 로그인 state 소비·세션 저장·refresh 잠금, HTTPS reverse proxy를 준비해야 합니다. proxy는 Host를 `TODO_PUBLIC_URL`과 일치하게 전달하고 `/api/chatgpt/respond` 응답 버퍼링을 꺼야 합니다. 클라우드에서는 `TODO_HOST=0.0.0.0`과 실제 공개 URL을 설정하고 `TODO_USAGE_MODE=chatgpt`를 유지합니다. 방문자의 WSL이나 Codex CLI는 필요하지 않습니다.

GitHub Pages 같은 정적 호스팅만으로는 OAuth 및 모델 호출 서버를 실행할 수 없습니다. 앱 서버가 필요하며 정적 호스팅에서는 연결 안내를 표시합니다. 할 일·루틴·브라우저 알림·사용량 숨김 설정은 계속 동작합니다.

## 저장 방식과 기기 간 동기화

로그인 전에는 할 일·루틴·카테고리·플랜·완료 기록·일정이 현재 브라우저의 `localStorage`에 저장됩니다. 마감은 할 일에 포함되며 기존 Supabase 문서 구조로 함께 동기화됩니다. 알림 시간과 GPT 표시 설정은 브라우저별로 저장합니다. 클라우드 동기화를 켜려면 Supabase 프로젝트를 연결해야 합니다. 로그인 후에는 사용자별 문서를 Supabase에 저장하고 다른 기기에서도 같은 계정으로 로그인해 불러옵니다. 데이터베이스 접근은 Supabase Auth와 Row Level Security 정책으로 로그인한 사용자 본인에게만 허용합니다.

Supabase 대시보드의 SQL Editor에서 [`supabase/schema.sql`](supabase/schema.sql)을 실행한 다음, Auth 설정의 Site URL과 Redirect URL에 GitHub Pages 주소를 추가하세요. GitHub 저장소의 **Settings → Secrets and variables → Actions → Variables**에 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`를 설정하면 배포 workflow가 공개 브라우저 설정 파일을 생성합니다. Publishable key는 브라우저에 포함되므로 `service_role` 키를 넣지 마세요.

여러 기기에서 동시에 같은 목록을 수정하면 마지막 저장이 우선 적용됩니다. 앱은 열려 있는 동안 10초마다 클라우드 변경을 확인합니다.

## GitHub Pages 배포

`main` 브랜치에 push하면 GitHub Actions가 사이트를 배포합니다. 저장소 설정의 **Settings → Pages → Build and deployment**에서 **GitHub Actions**를 배포 소스로 선택하세요. 배포가 끝나면 Pages 설정 화면과 Actions 로그에 사이트 주소가 표시됩니다.
